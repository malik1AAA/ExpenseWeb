# Debt Form Documentation

## Overview
The Debt Form is a modal component used for adding and editing debts in the Finance Tracker application. It provides a user-friendly interface for managing both lent and borrowed money with proper validation and auto-generated IDs.

## Features

### Form Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| **Person** | Text | ✅ Yes | Name of the person involved in the debt |
| **Direction** | Select | ✅ Yes | Whether money was lent or borrowed |
| **Debt Category** | Select | ✅ Yes | Category of the debt (Cash or Food) |
| **Original Amount** | Number | ✅ Yes | Initial amount of the debt (must be > 0) |
| **Date** | Date | ✅ Yes | Date when the debt was created |
| **Due Date** | Date | ❌ Optional | Expected repayment date |
| **Notes** | Textarea | ❌ Optional | Additional notes about the debt |

### Direction Options

The Direction field has two options with clear descriptions:

1. **Lent - Money I should receive back**
   - Use this when you gave money to someone
   - They owe you money
   - Shows as green in the UI

2. **Borrowed - Money I need to pay back**
   - Use this when you took money from someone
   - You owe them money
   - Shows as red in the UI

A dynamic help text appears below the Direction field explaining what the selected direction means.

### Debt Category Options

1. **Cash** - Monetary debt
2. **Food** - Debt for food/groceries

## Validation Rules

### Required Fields
- **Person**: Cannot be empty or whitespace only
- **Original Amount**: Must be a number greater than 0
- **Date**: Must be selected

### Optional Fields
- **Due Date**: Can be left empty
- **Notes**: Can be left empty

### Validation Messages
- Person: "Person is required"
- Original Amount: "Amount must be greater than 0"
- Date: "Date is required"

## Auto-Generated Fields

### DebtID
- Automatically generated when creating a new debt
- Format: `DEBT` + timestamp + random string
- Example: `DEBTm5x7k9p2q`
- Generated by `FinanceContext.addDebt()` function
- Uses the `generateId('DEBT')` helper function

## Component Props

```javascript
DebtForm.propTypes = {
  isOpen: PropTypes.bool.isRequired,        // Controls modal visibility
  onClose: PropTypes.func.isRequired,       // Callback to close modal
  onSubmit: PropTypes.func.isRequired,      // Callback with debt data
  debt: PropTypes.object,                   // Existing debt for editing (null for new)
  defaultDirection: PropTypes.string,       // Default direction ('lent' or 'borrowed')
}
```

## Usage Examples

## Data Flow

### Adding a New Debt
1. User fills out the form
2. Form validates all required fields
3. On submit, `onSubmit(debtData)` is called
4. Parent component calls `FinanceContext.addDebt(debtData)`
5. Context auto-generates `DebtID`
6. New debt is added to the state
7. Modal closes

### Editing an Existing Debt
1. User opens form with existing debt data
2. Form pre-fills all fields
3. User modifies fields
4. Form validates all required fields
5. On submit, `onSubmit(updatedDebtData)` is called
6. Parent component calls `FinanceContext.updateDebt(id, updatedDebtData)`
7. Debt is updated in the state
8. Modal closes

## Form State Management

The form uses React's `useState` hook to manage:
- `formData`: Object containing all form field values
- `errors`: Object containing validation error messages

### Form Reset
- When opening for a new debt: All fields reset to defaults
- When opening for editing: All fields pre-filled with debt data
- Date field defaults to current date for new debts

## Integration with FinanceContext

The form works seamlessly with `FinanceContext`:

```javascript
// In Debts.jsx
const { addDebt, updateDebt } = useFinance();

const handleFormSubmit = (debtData) => {
  if (editingDebt) {
    updateDebt(editingDebt.DebtID, debtData);
  } else {
    addDebt(debtData);  // DebtID auto-generated here
  }
};
```

## Schema Compliance

All field names use constants from `excelSchema.js`:
- `COLUMNS.DEBTS.PERSON`
- `COLUMNS.DEBTS.DIRECTION`
- `COLUMNS.DEBTS.DEBT_CATEGORY`
- `COLUMNS.DEBTS.ORIGINAL_AMOUNT`
- `COLUMNS.DEBTS.DATE`
- `COLUMNS.DEBTS.DUE_DATE`
- `COLUMNS.DEBTS.NOTES`

This ensures consistency across the application and makes it easy to update field names in the future.

## UI/UX Features

1. **Responsive Design**: Grid layout adapts to screen size
2. **Real-time Validation**: Errors clear as user types
3. **Helpful Placeholders**: Example values in input fields
4. **Clear Labels**: All fields have descriptive labels
5. **Required Indicators**: Asterisk (*) shows required fields
6. **Dynamic Help Text**: Direction field shows contextual help
7. **Modal Interface**: Non-intrusive form presentation
8. **Cancel/Submit Buttons**: Clear action buttons at bottom

## Error Handling

- Validation errors display below each field in red
- Form cannot be submitted until all validation passes
- Errors clear automatically when user corrects the field
- No backend errors (all validation is client-side)
